Segurança

Semelhante às fortificações medievais, é recomendado fornecer aos seus servidores múltiplas camadas de defesa. Certifique-se de usar Firewalls, Senhas fortes, SSH e mantenha seus servidores atualizados com todo o software utilizado. Isso inclui o sistema operacional, FreeSWITCH e FusionPBX.

FusionPBX O script de instalação mais recente do Debian configura o firewall IPTables para você. As ramais do FusionPBX definem senhas fortes por padrão. Você pode aumentar a complexidade da senha usando as configurações em Avançado > Configurações Padrão para aumentar o comprimento das senhas geradas por padrão.

Firewall Embora o novo script de instalação tenha configurado o IPTables para você, é recomendado que você revise as configurações. No Debian e Ubuntu você pode verificar seu firewall com o seguinte comando.

    iptables -L

SSL / TLS

SSL e TLS são muito necessários nas aplicações de internet atuais, desde VOIP até sites. O FusionPBX usa por padrão um certificado autoassinado. No entanto, você pode usar provedores de certificados onde pode comprar certificados, e também existem opções gratuitas. Com multi-inquilinos baseados em domínio, certificados curinga podem ser úteis. Além disso, ao decidir qual provedor de certificados usar, você deve consultar a documentação do fabricante do telefone para encontrar um que seja compatível com o provisionamento HTTPS.

Let's Encrypt fornece certificados gratuitos para um único domínio e agora também suporta certificados curinga.

Atualização

Problemas de segurança são corrigidos à medida que são descobertos e são atualizados para o master e o lançamento mais recente. As atualizações são consideradas uma parte importante para manter o servidor seguro. As atualizações sempre precisam ser feitas no sistema operacional, FreeSWITCH e FusionPBX.

O script de instalação mais recente instalará os pacotes do FreeSWITCH por padrão. Para atualizá-los e aos pacotes do sistema operacional, execute os seguintes comandos.

    apt-get update
    apt-get upgrade

Se você precisar de ajuda para atualizar com segurança, considere o suporte pago.

XML RPC

Na nova instalação, o mod[xml_rpc]{#xml_rpc} não está habilitado por padrão. É recomendado executar um firewall em todos os servidores FusionPBX. O script de instalação mais recente do Debian configura o firewall por padrão. No entanto, é recomendado verificar se ele está instalado e em execução.

O Mod[xml_rpc]{#xml_rpc} permite executar comandos remotos no FreeSWITCH. Certifique-se de ter um firewall protegendo a porta XML RPC. Considere alterar a senha do XML RPC. A página Avançado > Configurações na interface permite alterar a senha ou a porta. No mínimo, não permita acesso público à porta XML RPC.

O script de instalação mais recente do Debian instala o firewall iptables que impede o acesso público à porta mod[xml_rpc]{#xml_rpc}. Se você não estiver usando um firewall no servidor, deveria, mesmo que ele seja protegido por um firewall externo. Algum colega de trabalho desinformado pode expor o servidor à internet pública em algum momento no futuro. Múltiplas camadas de segurança são consideradas a melhor prática.

O XML RPC é seguro por padrão por 2 motivos.

  • O módulo está desabilitado por padrão.

  • O script de instalação protege a porta XML RPC 8787 com firewall e não permite acesso a ela por padrão fora de 127.0.0.1.

Se você fosse iniciar o módulo e abrir a porta 8787 no firewall, você iria querer definir uma senha realmente forte para ele em Avançado > Configurações. Seria recomendado usar uma VPN como OpenVPN para acessar o XML RPC pela porta 8787 em vez de abrir a porta 8787 no firewall.

Fail2ban

O Fail2ban também é usado para proteger SSH, FreeSWITCH, o servidor web, bem como outros serviços. Você pode visualizar quaisquer endereços IP que foram bloqueados pelo Fail2ban com o seguinte comando.

    iptables -L

SSH

Use senhas fortes com SSH ou, melhor ainda, use chaves SSH para melhor proteção dos seus servidores.
